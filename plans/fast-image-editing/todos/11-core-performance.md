# 普通编辑与工程性能

## T1 · 建立端到端基准并按证据优化

前置依赖：07-groups-text-adjustment.md。本轮仅测试无需模型的直接编辑。

要做什么：建立可复现基准素材与脚本，登记 CPU/内存/OS/磁盘/线程/编译器/release 设置；至少 30 次新进程采样报告 p50/p95 与峰值内存、阶段耗时。覆盖 --version、1080p JPEG 缩放曝光饱和度、4K 调整、PNG 透明图、4K 多图层和大模糊；工程首次提交、清缓存重放、磁盘检查点恢复、重复预览、20 步修改第 18/3 步的耗时/重算/磁盘占用。区分 OS 文件缓存和工程缓存，不能伪称冷缓存。根据实测选择减少拷贝、等价点操作融合、缩放/编码和线程预算、检查点/缓存策略改进；不牺牲语义精度/采样/编码质量。

预计修改：基准脚本/素材生成与报告、pic-core 中经测量确认热点、必要 CLI 计时与文档/测试，本 todo/README。

验收条件：

- [ ] 所有普通编辑和工程场景均有 release 二进制端到端 30 次测量、p50/p95、运行条件和可重跑命令。
- [ ] 报告相对建议门槛的实际结果与未达标原因；无未经测量的加速承诺，libvips 未可用则如实说明对照限制。
- [ ] 优化有前后测量及解码像素/语义一致性证据；操作融合后任意逻辑步骤仍可观察。
- [ ] 线程/内存/磁盘预算可说明，不依赖降低质量；建立可运行的性能回归检查方法并避免不稳定 CI 门槛。
- [ ] 完整仓库校验通过。

验证：完整仓库校验；固定 release 基准至少 30 轮；像素/重放/检查点一致性回归；输出原始机器可读结果和简洁分析。
